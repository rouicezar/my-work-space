# Dual-model Supervisor protocol evidence — 2026-08-30

## Proven in this batch

- A cloud proposal is created offline from a canonical, non-streaming request whose
  model and output ceiling match the approved task contract.
- Pending outbound bytes and metadata are stored in product-owned `0700` state with
  `0600` files. A modified payload, unsafe identifier, or symlink fails closed.
- The native client passes outbound request bytes only through standard input. Prompt
  content does not enter process arguments.
- A DeepSeek key is read from product Keychain state by the native layer and passed to
  Supervisor only through the child environment. It is not generated by the product.
- Approval is one-shot, expiring, and bound to proposal, correlation, provider, model,
  payload digest, output ceiling, and maximum cost. Approval and denial are audited.
- Cloud results normalize content, tool proposals, token usage, and computed cost.
  Tool proposals are data only and do not bypass the product tool-policy boundary.
- Pending outbound bytes are removed after denial or an execution attempt.
- The signed temporary application contains the frozen Supervisor and the pinned
  `cloud-providers.json` resource. The frozen executable advertises all four cloud
  protocol commands.
