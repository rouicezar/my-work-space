# ADR 0009: Versioned Supervisor-to-App Protocol

Status: accepted for implementation, 2026-08-29.

## Context

The repository already has authoritative Python implementations for hardware preflight, artifact verification, recoverable installation, model integrity and health. Reimplementing their decisions in Swift would create two truth sources. The native app instead needs a stable, bounded and testable process protocol that can later be backed by a self-contained bundled helper.

## Decision

- The Supervisor exposes commands through a direct child process, never a shell.
- Every response is one JSON envelope with `schema_version`, `command`, `request_id`, `status`, `payload`, `error` and `emitted_at`.
- `status: ok` means the command executed and its payload is authoritative. A preflight payload may still report `supported`, `unknown` or `unsupported`.
- Protocol, invocation or internal failures use `status: error`, a stable error code and a nonzero exit status. Tracebacks are never part of the public response.
- Request IDs are generated by the caller and echoed exactly for correlation.
- Secrets, prompts, credentials and personal paths are excluded from protocol payloads. The app passes explicit product-owned paths when a command requires them.
- The Swift client accepts only an absolute executable, invokes a fixed command vocabulary, enforces an output bound and rejects schema, command or request-ID mismatches.

## Packaging boundary

During development the protocol entry is a Python executable that calls the existing implementations. It is not yet a distributable dependency. Before Alpha, the app bundle must contain a self-contained signed Supervisor helper or runtime, and the UI must resolve only that bundled helper. Absence remains an explicit unavailable state and never triggers a second native implementation.

## Initial command

`preflight` is the first read-only command. It delegates to the existing preflight implementation and returns its unchanged report inside the protocol envelope. Installation, model linking, lifecycle and health commands will join only after their consent, progress, recovery and cancellation semantics are specified.
