# Forma AI 完整产品简介与使用指南

> 文档定位：这是 Forma AI 完整开发结束并通过发布验收后的目标正式版用户文档。在正式发布门槛全部通过前，它用于定义最终用户体验与验收标准，不代表当前开发版本已经具备全部能力。

## 1. 一句话认识 Forma AI

Forma AI 是一款面向 Apple Silicon Mac 的本地优先、多 Agent AI 工作台。你只需要描述目标，它就能在统一界面中选择合适的本地或云端模型、组织多个 AI Agent、调用你授权的工具、保留可追溯的长期记忆，并让每一次重要外部操作都经过预览、批准、执行和验证。

它不是四个技术组件的启动器，也不是只会聊天的模型外壳。它把本地推理、多 Agent 执行、受治理记忆、工具连接、权限控制和故障恢复组合成一个普通用户可以直接使用的 Mac 产品。

## 2. 它适合谁

- 希望在 Mac 上完成研究、写作、整理、规划、编码和重复性知识工作的普通用户。
- 希望敏感内容优先留在本机，同时在必要时选择云端模型的个人与团队。
- 希望让多个 AI Agent 分工协作，但仍能看见状态、成本、权限和结果依据的专业用户。
- 希望把文件、应用和业务工具接入 AI 工作流，同时保留逐项授权与审计记录的用户。
- 希望拥有可纠正、可删除、带来源的长期知识，而不是不可解释的聊天“记忆”的用户。

如果你的设备不是受支持的 Apple Silicon Mac，或者你的工作必须依赖未经支持的专有系统、实时硬件控制或完全无人监管的高风险自动化，Forma AI 可能不适合你。

## 3. Forma AI 能做什么

### 3.1 统一完成日常知识工作

你可以直接创建任务，例如：

- “比较这三份方案，列出证据、分歧、风险和建议。”
- “根据这个资料目录写一份有来源的中文报告，并生成英文摘要。”
- “分析这个代码仓库，先提出修复计划，测试通过后再提交。”
- “把会议材料整理为决定、负责人、截止时间和待确认问题。”
- “把这批文件分类、重命名并生成索引；执行前先让我确认变更清单。”

Forma AI 会把目标、资料、限制、验收条件和权限要求组织为一个可追踪任务，而不是把它们压缩成一次不可恢复的对话。

### 3.2 本地优先使用 AI

默认情况下，Forma AI 通过 oMLX 在你的 Mac 上运行经过验证的本地模型。适合本地完成的任务会留在本机，例如摘要、分类、结构化提取、记忆检索、低风险路由和部分写作任务。

当本地模型的上下文、模态、工具或质量门槛不足时，Forma AI 不会偷偷切换到云端。它会说明原因，并展示一次性云端提案，包括供应商、模型、将要发送的数据、处理位置、隐私提示、最大输出、预计成本和关联审计编号。只有你批准的那一次请求可以发送。

### 3.3 组织多个 Agent 并行协作

Forma AI 使用 Herdr 作为多 Agent 执行核心。一个复杂任务可以被拆分为研究、分析、实现、测试和复核等工作单元。你可以查看每个 Agent 的负责人、状态、日志、产物、阻塞与权限请求，并可以暂停、取消或恢复。

系统只会在子任务达到定义好的验收条件后汇总结果。Agent 数量多不等于结果正确；最终输出仍会显示验证状态和未解决问题。

### 3.4 建立受治理的长期记忆

Forma AI 使用 Semantica 管理长期知识。原始输入、运行日志、候选知识和已确认知识彼此分离。

- 新信息不会因为出现在对话里就自动成为长期事实。
- 候选知识需要来源、时间和任务关联。
- 重要事实或决定需要确认后才进入权威记忆。
- 你可以查看来源、修正内容、查看版本历史、导出或删除。
- 删除和纠正不会被旧版本悄悄覆盖。

### 3.5 安全连接工具和应用

安装的连接器可以提供文件、浏览器、日历、任务、数据库或其他应用能力。每个连接器分别声明读取、写入、发送、删除、执行和凭证权限。

读取不自动获得写入权，写入不自动获得发送或删除权。重要操作会先显示对象、范围、变化、影响和验证方法。你可以批准一次、拒绝、缩小范围或撤销连接器权限。

### 3.6 保存历史、审计和恢复状态

每项重要任务都有稳定 ID 和关联审计记录。你可以看到任务是完成、部分完成、被拒绝、失败、已取消还是已回滚。重启应用或 Mac 后，持久任务可以从经过核对的状态继续，而不是被错误标记为完成。

## 4. Forma AI 的核心优势

1. **本地优先，而不是本地口号。** 本地路径必须通过真实推理和资源检查；云端路径必须经过逐次预览与批准。
2. **多个 Agent 可见、可控、可恢复。** 你能看到谁在做什么，能取消、继续和检查产物，而不是只等待一个黑盒答案。
3. **长期记忆有来源、有版本、可删除。** 系统区分“听过”“候选”和“已确认”，减少错误信息长期污染。
4. **重要动作先预览，执行后验证。** 外部写入、发送、删除、运行命令和云端传输都有明确权限边界。
5. **失败会如实显示。** 缺少能力、网络失败、凭证错误、模型不可用和验证失败不会被包装成空结果或成功。
6. **一个产品承担生命周期。** 安装、初始化、启动、停止、更新、回滚、恢复和卸载由统一界面管理，不要求普通用户维护端口和脚本。
7. **组件可替换。** 模型、Agent 和工具通过版本化适配协议连接，避免把你的工作锁死在单一供应商中。

## 5. 它的能力边界

能力边界不是故障，而是 Forma AI 用来保护质量、隐私和可恢复性的规则。

| 边界 | Forma AI 的行为 |
|---|---|
| 本地模型能力不足 | 说明缺口；在云端已配置时生成一次性提案，否则给出可行替代方案 |
| 高风险外部操作 | 要求明确预览和范围化批准；拒绝或超时则不执行 |
| 缺少可靠证据 | 标为假设、待验证或未知，不把推断写成事实 |
| 工具或供应商不可用 | 说明受影响能力和恢复步骤，不静默换用另一个供应商 |
| 任务无法完整验证 | 返回部分完成及未通过项目，不宣称全部完成 |
| 设备资源不足 | 推荐更小模型或限制并发；不强行启动不安全配置 |
| 记忆存在冲突 | 保留冲突与来源，要求确认后再更新权威记录 |
| 连接器权限不足 | 请求最小新增权限，或提供不改变外部状态的替代流程 |

## 6. Forma AI 不能做什么

- 它不能保证 AI 输出永远正确。重要事实、法律、医疗、财务、安全和生产变更仍需要合格人员复核。
- 它不能代表你承担决策责任，也不会把“用户批准”解释为无限授权。
- 它不能绕过 macOS、组织系统或第三方服务的权限、政策和使用条款。
- 它不能在未经预览和批准时发送云端数据，也不能保证第三方供应商永远在线或永不改变政策。
- 它不能自动把所有对话写入长期记忆；未经确认的信息不会成为权威事实。
- 它不能访问未连接、未授权或当前不可用的文件、应用、账号和设备。
- 它不能把没有可验证接口的现实世界结果假装成已完成。例如“邮件已送达”“付款已结算”“部署已生效”必须有对应验证证据。
- 它不是杀毒软件、备份系统、密码管理器或合规认证机构。你仍应使用专门工具承担这些职责。
- 它不会为提高速度而静默关闭审计、越过审批或把任务发送给另一个云端供应商。
- 第一版不支持 Intel Mac；受支持的 macOS、内存、磁盘和模型范围以应用内支持矩阵为准。

## 7. 首次启动：建议用 10 分钟完成这些步骤

### 第一步：完成设备检查

打开 Forma AI 后，首次设置会检查芯片、macOS、可用内存、磁盘空间和端口冲突。确认状态为“受支持”或阅读“未知”项的解释。不要把“未知”当成已通过，也不必把它误解为不支持。

### 第二步：选择本地模型配置

接受推荐配置，或根据磁盘、速度和质量需要选择其他受支持模型。界面会显示下载量、安装占用、模型能力和许可证。已有经过验证的模型可以零复制引用；Forma AI 不会擅自删除外部缓存。

### 第三步：安装并验证本地运行环境

批准安装计划后等待下载、校验和安装完成。中断可以恢复。安装结束后运行“验证示例任务”。只有真实模型响应通过，状态才会变为“本地 AI 就绪”。

### 第四步：设置记忆

选择本地语义检索模型，阅读存储位置、维度、磁盘占用和删除策略。完成真实检索测试后再启用长期记忆。建议最初使用“每次确认后写入”。

### 第五步：检查权限默认值

进入“设置 → 权限与批准”，保持以下推荐规则：

- 读取可以按目录或连接器授权。
- 写入、发送、删除和执行始终要求预览。
- 云端每次询问。
- 凭证只保存在 macOS Keychain。
- 高风险操作不允许永久批准。

### 第六步：按需配置云端模型

如果你需要云端能力，在“模型与供应商”中添加自己的 API Key，运行低成本连接测试并阅读供应商数据处理说明。云端默认关闭；保存凭证不等于批准发送任何任务。

### 第七步：连接第一个工具

从一个低风险、可撤销的连接器开始。先只授予读取权限，运行一次只读任务，再测试一个有明确预览和验证方式的可逆写入。

### 第八步：运行你的第一个真实任务

建议使用小而清晰的任务：

> 阅读我选择的三份文档，分别列出事实、观点和未验证判断；生成一页摘要。只读取文件，不修改原文件，不使用云端。验收条件：每条关键结论都标注来源文件。

任务完成后查看结果、来源、模型路径、Agent 状态和审计记录。

## 8. 主界面怎么用

- **New task：** 创建工作、继续对话、查看执行状态和处理批准请求。
- **History：** 查找已完成、进行中、中断、失败或取消的任务，并恢复符合条件的任务。
- **Settings：** 管理通用设置、模型与供应商、Agent 与工具、记忆、权限与批准、本地运行时、数据与隐私、诊断与恢复。

普通使用应从 New task 开始。只有设置能力、处理故障或审查数据时才需要进入 Settings。

## 9. 如何写出好任务

一个高质量任务通常包含五部分：

1. **目标：** 最终要得到什么。
2. **材料：** 可以读取哪些文件、目录、链接或连接器。
3. **限制：** 哪些内容不能改、不能发送或不能假设。
4. **过程：** 是否需要并行 Agent、先计划、先研究或先征求批准。
5. **验收：** 如何判断完成，输出格式是什么，需要哪些证据。

推荐模板：

> 目标：……  
> 可用材料：……  
> 禁止事项：……  
> 执行要求：……  
> 验收标准：……  
> 输出位置/格式：……

不要只写“帮我优化一下”。更好的写法是：“保留原意，把这份 2,000 字中文说明压缩到 1,200–1,400 字；目标读者是第一次使用的非技术用户；不得增加未提供的产品承诺；输出修改稿和五条主要改动。”

## 10. 如何理解状态和批准

- **Local：** 任务数据由已验证的本地路径处理。
- **Cloud proposal required：** 尚未发送；需要你检查一次性云端提案。
- **Capability unavailable：** 当前安全路径无法满足任务，系统没有偷偷降级。
- **Needs attention：** 某个 Agent、工具、模型或权限需要处理。
- **Partial：** 部分产物有效，但仍有明确未完成项。
- **Failed safely：** 任务停止，未把失败包装成成功；查看恢复建议。

批准前重点检查：发送对象、数据范围、外部影响、最大成本、有效期、是否可撤销，以及系统准备怎样验证执行结果。

## 11. 如何用好多个 Agent

- 让并行工作彼此独立，例如“来源核查”“方案比较”“风险审查”，避免多人同时修改同一个文件。
- 给每个 Agent 明确产物与验收条件。
- 对写操作指定唯一负责人；其他 Agent 只提供建议或审查。
- 在长任务中设置阶段检查点，先确认研究和设计，再进入实现。
- 汇总时要求列出一致结论、分歧、证据不足和被放弃方案。
- Agent 被阻塞时先解决权限、输入或依赖问题，不要无条件重复运行。

## 12. 如何使用记忆

- 只保存未来会重复使用且有来源的信息，例如项目决定、术语定义、已确认偏好和流程规则。
- 不要把临时猜测、一次性草稿或第三方敏感信息直接确认为长期记忆。
- 定期查看候选、冲突和过期记录。
- 修正事实时说明新证据；不要只覆盖旧内容。
- 离开项目或组织前导出需要保留的记录，并删除不再有合法用途的数据。

## 13. 隐私与安全建议

- 先使用本地路径，再考虑云端提案。
- API Key 只在应用的安全凭证界面输入，不要粘贴到任务、日志或文件中。
- 给连接器最小权限；优先按目录、项目、账号或动作范围授权。
- 对发送、删除、付款、发布和生产部署逐项检查预览。
- 分享诊断包前查看脱敏摘要。
- 定期检查云端提供商、连接器和长期批准；不再使用时立即撤销。
- 重要文件仍应有独立备份。任务恢复记录不能替代备份。

## 14. 出现问题时怎么处理

1. 先阅读错误分类、受影响能力和数据风险。
2. 打开“设置 → 诊断与恢复”，刷新组件与工作流状态。
3. 优先使用应用提供的安全重试、恢复、停止或回滚操作。
4. 不要在不理解影响时反复安装、删除状态目录或手动终止进程。
5. 导出已脱敏的诊断包和任务关联 ID，再联系支持。
6. 如果涉及外部写入，先到目标系统确认是否已发生，再决定重试，避免重复发送或重复创建。

## 15. 更新、回滚和卸载

更新前，Forma AI 会检查版本、磁盘、组件兼容性和数据迁移计划。更新失败时可以恢复或回滚到已验证版本，不会把半完成迁移标记为成功。

卸载时你可以选择：

- 保留本地模型和受治理数据；
- 导出后删除产品数据；
- 删除产品管理的数据和凭证；
- 保留外部拥有的模型缓存或独立应用。

卸载摘要会明确哪些内容被删除、哪些内容仍保留以及如何恢复。

## 16. 常见问题

### Forma AI 会自动把我的文件上传吗？

不会。默认使用本地路径。任何云端传输都需要显示具体数据与成本的一次性批准。

### 配置了 DeepSeek 后，所有任务都会发到云端吗？

不会。配置凭证只增加一个可选能力；本地路径仍是默认，且每次云端传输都要单独批准。

### 多 Agent 是否一定比单 Agent 更好？

不是。简单任务会使用更小的执行方案。只有可并行、需要不同专长或独立复核时，多 Agent 才有价值。

### Forma AI 会记住所有对话吗？

不会。对话、审计、候选知识和已确认长期记忆是不同数据层。只有符合规则并经过确认的内容才进入权威记忆。

### 我可以完全无人值守运行吗？

低风险、预先定义且可验证的任务可以按策略自动运行；云端传输和高风险外部操作仍受批准规则约束。Forma AI 不提供无限制的永久授权。

### 如何获得最好效果？

提供清楚目标、可靠材料、明确限制和可验证验收条件；从小任务开始，检查证据与审计，再逐步扩大连接器权限和自动化范围。

## 17. 推荐的第一周使用方式

- 第 1 天：完成本地运行、记忆与权限设置，运行只读文档任务。
- 第 2 天：建立一个带来源的项目记忆，并练习修正与删除。
- 第 3 天：连接一个低风险工具，完成只读任务。
- 第 4 天：完成一次带预览和验证的可逆写入。
- 第 5 天：尝试一个多 Agent 任务，观察分工、阻塞和汇总。
- 第 6 天：在非敏感任务上体验一次云端提案，认真检查数据与成本。
- 第 7 天：检查历史、审计、权限和记忆，收紧不需要的授权并保存常用任务模板。

最好的使用原则是：先让 Forma AI 证明它能安全完成小任务，再逐步扩大任务复杂度、数据范围和操作权限。
